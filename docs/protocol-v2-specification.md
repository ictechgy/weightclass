# Protocol 2 normative contract freeze

Status: the contract was frozen before dispatch and is now implemented through
native and delegation protocol-2 review/run. The prior five-round RALPLAN ended
`max_rounds/ITERATE`; it is mandatory review input, but is **not consensus-approved**.
No production v2 dispatch was enabled by the contract-freeze goal itself.
Protocol-2 rollback removes only v2 dispatch and its
artifacts; legacy behavior remains in place.

## Shared scalar, privacy, and version rules

All objects have exactly the keys catalogued in `tests/fixtures/{native_v2_schema,delegation_v2_schema}/contract.json`; unknown keys fail. Required and explicitly nullable keys are exhaustive. “Integer” always means a JSON integer with `bool` excluded. IDs are nonempty UTF-8, at most 64 bytes, contain no whitespace/control/invisible characters, and live in the catalogued namespace. Opaque labels are nonempty reviewable UTF-8 of at most 240 bytes and are declarations, never evidence of account, subscription, entitlement, recipient, billing, permission, model, or effort actually used. Paths are reviewable UTF-8 and bounded as catalogued.

All policy, manifest, and descriptor inputs are at most 262144 bytes. Bounds are checked before graph or pairwise work. Errors are value-free JSON classes: malformed/ambiguous/version-mixed input is `{"error":"invalid_input"}`/exit 2; an otherwise valid but unavailable route is `unsupported_route`/exit 3; executor observation failure is `executor_unavailable`/exit 4; and acknowledgement mismatch is exit 6. No diagnostic, representation, fingerprint, test name, or persisted artifact may contain, echo, log, or hash task content.

Canonical JSON is UTF-8 from `json.dumps(..., ensure_ascii=True, allow_nan=False, sort_keys=True, separators=(",", ":"))`. The fingerprint payload is the complete canonical descriptor minus only its top-level `route_fingerprint`; the fingerprint is `sha256:` plus 64 lowercase hex characters. Every list has an exhaustive registered path and the ordering in the fixture catalog. Canonicalization never infers omitted data.

The frozen **14-stage validation order** is: (1) exact keys/types/scalar and collection bounds; (2) local uniqueness and enums; (3) global namespaces; (4) references and producer ownership; (5) edge/ordered-pair uniqueness and gate ownership; (6) combined-DAG cycle/topological validation; (7) terminal validation; (8) input/projection one-to-one binding and types; (9) strict ancestry; (10) central write predicate and scope conflicts; (11) structural transitions; (12) directional grant matching and unused-grant rejection; (13) canonical sorting and descriptor-size check; (14) fingerprint binding. Tests assert only the redacted class and exit precedence.

## Native policy schema 2

The top-level exact keys are `schema_version`, `profiles`, `execution_targets`, `routes`, `profile_grants`, and `vendor_grants`; none are nullable. `schema_version` is integer 2. Collection maxima are respectively 64, 64, 128, 128, and 128; every required selection collection is nonempty. Exact nested shapes, field types, ownership, references, descriptor projections, statuses, and ordering appear in the native contract fixture and are normative, not illustrative.

An eligibility selector is exactly `(source_vendor, source_profile_id, tier)`, is globally unique, and references an existing profile whose vendor equals `source_vendor` before uniqueness or grant analysis. A target, destination profile, vendor, and builder form one coherent chain. Allowed `(model, effort)` pairs are nonempty, unique, and limited to 64 per target. The compiled descriptor separately projects the source profile, selected route, destination target, selector, argv, and one explicit source-to-destination transition; it never overloads one `profile` field to mean both endpoints.

Same-profile routing consumes no profile grant. A changed profile consumes exactly one directional profile grant. A changed vendor additionally consumes exactly one directional vendor grant. Equal-endpoint, unknown, duplicate, reverse-only, ambiguous, redundant, and unused grants fail; one unique grant may serve repeated identical transitions.

Builders are closed. Codex argv is `[exe,"exec","--ephemeral","--sandbox","workspace-write","--model",model,"-c","model_reasoning_effort="+effort,"-"]`. Claude argv is `[exe,"--print","--no-session-persistence","--permission-mode","acceptEdits","--model",model,"--effort",effort]`. There is no free-form argv, command, environment, endpoint, auth, fallback, settings source, or profile override. `argv[0] == executable`; argv is at most 32 tokens, 4096 bytes per token, and 16384 bytes aggregate.

Absent `schema_version` remains unchanged schema 1. Exact integer 1 strips only that validated key and invokes the unchanged schema-1 path with byte-identical output. Exact integer 2 selects schema 2. Boolean, wrong type, or unsupported values fail exit 2 without fallback. Native `route`/`run` may parse `--source-profile`, but built-ins/schema 1 reject it semantically; schema 2 requires both source fields. Legacy `render` does not parse it.

Schema-2 `run` requires exact acknowledgement. Missing acknowledgement exits 6 before task access. A supplied mismatch is checked after applicable task work and selection, but before observation or spawn. Without `--tier`, task classification occurs exactly once; with it, classification is never called.

`ValidatedTaskV2` is created by one binary `limit + 1` read (production: `sys.stdin.buffer`; injected `StringIO`: encode its single bounded text read), strict UTF-8 decode, byte-identical re-encode, and existing semantic validation. It exposes only `classification_text()` and `delivery_bytes()`, has constant value-free representation, and has no equality, hash, or serialization. Schema 1 retains its current text reader and WCD1 string path.

`CompiledExecutionV2` contains only canonical descriptor bytes, fingerprint-payload bytes, route fingerprint, exact argv tuple, executable, closed transport/version, and frozen cleanup. Review, acknowledgement, inspection, WCD2, and spawn consume that one truth; command components are never rebuilt.

`ExecutableObservation` is frozen and records lexical path, `st_dev`, `st_ino`, file type/mode, size, `mtime_ns`, `ctime_ns`, and the POSIX `mode & 0o111 != 0` executable result. Final-component `lstat` rejects symlinks and nonregular/nonexecutable files; zero-sized regular executable files are allowed. Observe once and again immediately before spawn, require exact equality, and recheck executable equals `argv[0]` at the seam. Intermediate-component symlinks and replacement after the second check remain residuals; this is not inode-bound execution.

## Delegation policy, manifest, and protocol 2

Only the exact tuple policy 2, manifest 2, descriptor 2, runtime protocol 2, WCD2 is valid. Mixed/wrong/unsupported tuples fail exit 2 with no fallback. **Protocol 2 is categorically ineligible** for `--require-qualified-runtime` and fails exit 3 before confirmation, acknowledgement, executable inspection, or task access. Protocol-1 lifecycle, qualification, empty registry, and WCD1 remain untouched.

The closed provider mapping is `openai -> codex` and `anthropic -> claude`. Policy, manifest, runtime, provider-family mapping, and eligibility are distinct exact-key objects. A manifest names reviewed runtime records; each runtime binds one absolute lexical path to one adapter, and each adapter declares its provider family, provider, build identity, supported transports, and capabilities. The selector is exactly `(source_vendor_family, source_profile_id, tier)`. Its profile must exist and map to the selector family before selector uniqueness, endpoints, transitions, or grants. An adapter binds to a task when its `provider` equals the destination profile provider, its `vendor_family` equals that provider’s mapped family, its supported transports include the destination profile transport, and its capabilities cover the task request. Adapter provenance does not require equality with the source family, so an authorized cross-vendor destination remains possible.

Every profile declares all five routing dimensions—provider, intended recipient, billing boundary, transport, and opaque account profile—plus capabilities and an exact nonempty allowed `(model, effort)` pair list. These labels are reviewable configuration, never inferred subscription or entitlement facts. The selected task pair must appear exactly in its destination profile. Requested orchestration provenance is explicit and non-authoritative: a workflow carries `requested_run_id`; every task carries `requested_task_id`, `requested_dispatch_id`, and `owner_role`. The router preserves these values for review without claiming that an external orchestrator actually created or completed the run, task, or dispatch.

Every source-to-root, dependency edge, and gate edge creates a distinct transition, even when endpoint values repeat. Endpoint comparison order is provider, intended recipient, billing boundary, transport, profile; `router_profile_id` is provenance, while `profile` is the opaque account-profile label. Every changed dimension consumes exactly one directional workflow-local grant; every declared grant is used, and one unique grant may serve repeated identical transitions.

For `synthesized`, `terminal_task_id` is non-null, exists, is the sole synthesizer and unique combined dependency+gate DAG sink, is reachable from every task, and has no outgoing edge. For `raw_independent`, it is null, there is no synthesizer, and disconnected rooted components are allowed. There is deliberately no tautological “reachable from some root” invariant.

A gate names its producer task/output with required type `weightclass.gate/v1` and the only predicate `{operator: equals, value: approved}`; multiple consumers may share an output, but every gate edge owns a transition. Output, artifact, projection, and edge IDs use distinct global namespaces and exact producer ownership; artifacts are owned by their containing output and carry only a global ID plus a bounded reviewable media-type label. Nothing is inferred from names, types, text, or proximity.

Inputs and projections are task-level sibling lists. Root tasks may have both empty. Input is `{id,type}`; projection is `{id,input_id,producer_task_id,producer_output_id}`. Input IDs are consumer-local, projection IDs global, and both lists are limited to 32. Every input has exactly one projection, counts match, the producer output exists and belongs to the named task, types match exactly, and the producer is a strict ancestor in the combined DAG. Canonical `/tasks/*/inputs` sorts by input ID and `/tasks/*/projections` by projection ID; both belong to the exhaustive list registry.

`task_requests_write()` is the sole derived write predicate: filesystem `write`, command `allow`, worktree `mutable`, or any allow-listed write capability is write-capable. Equal or ancestor/descendant mutable-scope overlap between write-capable tasks fails. Permission, worktree, tool, output, artifact, settlement, cleanup, and request vocabularies and bounds are frozen in the delegation catalog. Settlement is only an external settlement request and remains runtime-unverified. Direct-child exit is a separate lifecycle observation; zero is not task, orchestration, synthesis, gate, or settlement success.

Delegation limits are: workflows 32, profiles/adapters 64 each, tasks 32, dependency edges 128, gates 64, derived transitions 224, grants 128 per dimension, capabilities 32 per owner, outputs 64 per task, artifacts 128 total, mutable scopes 16 per task, instructions 16384 bytes/task and 131072 total, turns 256, deadline 86400, concurrency 32, attempts exactly 1, and runtime path 4096 bytes.

WCD2 is independent of WCD1: exact bytes `b"WCD2" + u32be(descriptor_length) + u32be(task_length) + descriptor + task`, an exact 12-byte header and no trailing bytes. It accepts bytes only. Descriptor maximum is 262144, task maximum 80000, and total maximum 342156.

Both contract catalogs contain the exhaustive canonical list-path registry. A list is invalid if its descriptor path is absent from that registry; there is no implementation-defined ordering fallback. Native paths cover eligibility, allowed model-effort pairs, argv, changed dimensions, and authorizations. Delegation paths additionally cover profiles, adapter transports/capabilities, tasks, requests, inputs/projections/outputs/artifacts, mutable scopes, dependency and gate edges, transitions, every dimension-local grant list, and argv.

## Enforcement and legacy evidence

The fixture `status` values mean: `caller_requested` is opaque input; `structurally_enforced` is router validation/compiler behavior; `direct_child_observed` is only direct exit; `runtime_unverified` is a typed request delegated to the external runtime; `runtime_owned` has no router field or enforcement binding; and `not_adopted` is deliberately absent. Weightclass makes no effective model/account/billing/recipient/tool/sandbox/completion assertion and adds no retries, fallback, background work, descendant containment, provider HTTP, credentials, stdout parsing, persistence, or task hashes.

The g01 characterization suite freezes built-in route/fingerprint bytes, schema-1 CLI/error/task privacy, render and existing native process behavior via existing subprocess tests, delegation protocol-1 descriptor/runtime/qualification behavior, WCD1 bytes, the empty registry, V2 API routing, and the exact-two-artifact distribution verifier. It invokes only Python and test-owned fixtures, never a real provider or network API, and does not refactor protocol-1 lifecycle.

The named guarded evidence patches `subprocess.Popen`, `subprocess.run`, and INET socket creation in the current test process. Its claim is only that direct launch and socket calls made by that process reject INET and allow only registered resolved test-owned executables or exact Python harness prefixes with `shell=False` and absolute argv zero. It does not instrument child processes; behavior below an allowed CLI or harness is covered by separate test-owned fixture and lifecycle assertions, not by this guard. Build and extracted-sdist subprocesses remain outside the claim.
